# Codex 并行采集与凭据配对（2.8.1）

管理页「打票流水 → 单号定向打票」新增「并行获取凭证」。默认 10 路，可选 2–32 路；原「开始打票」保持串行。API 沿用 `POST /api/v1/admin/accounts/:id/manual-harvest`，新增 `collect_lanes`；省略、0 或 1 为串行。

## 并行采集

- 需要内置托管 Mihomo，采票代理为 `http://127.0.0.1:3101`。外部代理不具备本实现需要的通道管理能力，明确报错。
- 内核新增回环监听 `127.0.0.1:17893–17924`，每个监听绑定自己的 `CODEX-COLLECT-*` 选择器，未选择节点时指向 REJECT。升级时检查这些端口没有被其他进程占用。
- 每轮独占管理租约，避免订阅更新、国家扫描和 use-once 探测在采集中改动出口。并行、串行手动与后台采集互斥；后台遇到手动任务会跳过本轮。
- 每个候选节点在一轮中最多分配一次，尊重国家过滤和节点停用状态。开启 use-once 时，探测前持久化节点使用记录；停止或重启不会静默恢复节点。
- 「最大尝试次数」是所有通道和所有所选模型共用的预算。探测间隔按每个通道计算；每次探测使用新 session，不带旧票或旧 Cookie。
- 每个模型首次合格票据成功入库后取消其余请求；勾选「出票即停」则结束整个任务，否则继续其余模型。HTTP 401/403/429 停止本轮并记录冷却。停止按钮或页面断开取消在途请求并等待通道退出。
- 接纳票据须通过 HTTP 状态、完整响应终止、票据结构和时效检查；上游明确报告其他模型时拒绝接纳。响应缺少 model 字段时保留兼容行为，不把票据形态当作模型能力证明。

## 票据、Cookie 与出口

新采票请求带 Lite 标记和不执行的工具声明，成功后将票据、同次响应 Cookie、session、Lite 标记一起保存。采票不再从旧票注入 Cookie。后续业务请求恢复自己的凭据，继续遵守既有 240 秒 Cookie 注入窗口和合格响应更新规则；旧票没有 Lite 标记时保持旧请求头行为。

并行采到的票额外记录托管节点身份。后续 HTTP/WS 请求使用独立监听重新选择该节点，直到响应关闭才释放租约。节点已从采集池标记 used 时仍可用于对应票的业务请求；管理员明确停用、失败节点或国家规则排除的节点不可恢复使用。不保证节点服务商的实际出口 IP 永远不变，也不保证复用同一条物理 TCP/TLS 连接。

当前托管节点回选租约与采集共用管理互斥，长响应会等待或阻塞其他相关操作。它优先确保出口归属，不代表提高业务请求吞吐量。并行采集只在手动入口启用，不自动开启票据功能，也不会修改管理员现有开关。

## 来源与验证边界

并行通道设计参考 [ccodex-rotate v0.4.10](https://github.com/446599/ccodex-rotate/releases/tag/v0.4.10)，源提交 `1d6875fce5f88c54718d2a9d4872b87ce8ca06e1`；本项目按自身管理器、账号隔离、票据存储和 SSE 入口独立实现，未合并无关仓库历史。

新会话及 Cookie 配对流程参考用户提供的 `fenjue.zip`（SHA-256：`de5c31521e0025a44d52da8fe500fa712152ec79bf1b55cc75e58c9e023858a6`）。不依赖授权码文件，不引入“第一个 model 字段等于目标模型即成功”的判定，也不宣称保证模型质量。

回归覆盖预算竞争、取消、入库失败、旧 Cookie 隔离、Lite 兼容及真实 Mihomo 内核配合本地模拟出口的通道隔离；不以模拟测试代表真实模型请求效果。本版不新增数据库迁移。
