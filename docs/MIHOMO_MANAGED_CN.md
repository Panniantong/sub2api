# 网页管理 Mihomo（2.7.3 开发中）

在系统设置的 Codex 打票代理区选择 Mihomo，点击「检测并安装」。安装完成后填写 Clash/Mihomo YAML 订阅地址，点击「保存并应用」。运行就绪后点击「设为打票代理」并保存系统设置。多订阅可逐行输入或导入 TXT；可追加或替换，空输入保留已保存订阅并重新获取节点。

内核在 Sub2API 数据目录的 `mihomo-codex` 子目录运行，使用应用用户，不需要 sudo。当前支持 Linux amd64/arm64。内核版本固定为 v1.19.31，通过官方 Release asset 的 SHA-256 摘要校验；订阅仅导入 outbound proxies，不导入订阅里的监听器、规则和控制接口。

订阅 URL、节点凭据和控制器 secret 保存于权限 0600 的文件，API 不回显这些内容。更换配置前先获取节点并运行内核配置检查；配置失败保留旧设置。启动任务互斥且可查询，应用退出时关闭内核，应用启动时恢复已保存的内核配置。

节点支持连接检测、停用和手动恢复。启用“用后移出”时，打票探测串行占用一个固定节点，发送前持久化已用状态，完成后移出轮换组；异常退出也不会自动恢复该节点。失败、已用、停用节点需手动恢复，全节点移出时拒绝出站，不回退直连。节点显示名是匿名标识；enabled 只代表允许参加轮换，不保证网络连通。订阅当前通过「保存并应用」刷新，不在后台定时重新下载。

静态住宅代理单独保留最后保存的 URL，可从内核切回，并继续使用已有脱敏与热更新机制。账号业务代理不会因此改变。

## 国家／地区过滤

内核面板新增“不限制／排除所选／仅允许所选”规则、多选搜索和“排除香港”快捷项。默认不限制，升级不改变现有出口。启用过滤后，未检测或检测失败的节点默认不参与打票，可明确勾选允许未知地区。规则作用于普通轮换及用后移出的实际选点；全部排除时拒绝出站，不回退直连或被排除节点。手动停用、失败和已用状态独立保留，恢复节点不能绕过地区规则。

点击“检测出口地区”后，经独立临时 Mihomo 进程固定节点访问 `https://api.country.is/`，以出口 IP 的检测结果记录国家/地区，不根据节点名称或入口服务器 IP 推断。检测不会调用模型，不改变业务代理或主打票组；每批最多检查 20 个最久未检测的节点，并发上限为 2，单节点超时 12 秒。节点列表可单独复测，并显示地区和最近检测时间。新节点保持未知，不继承其他节点的位置。

地区结果保存在受限配置文件中，订阅更新时同一节点身份可保留结果；动态落地 IP、分流及地理库差异可能使实际模型请求的位置与最近检测不同，需主动重新检测。该规则不保证上游对任意地区的可用性。本次只扩展受管 Mihomo 节点，静态住宅代理仍使用原代理设置。

后台提供「提前准备备用」与「固定主用」策略；默认保留提前刷新行为，切换不清除有效票据或冷却。账号编辑区及列表提示可查看最近采集结果、HTTP 状态、下次允许探测时间和备用有效期。账号额度限流期间不执行采集。

## 旧 systemd 内核迁移

root 二进制安装/升级流程检测到旧机场服务后，调用 `migrate-mihomo-managed.sh`：暂存旧订阅与节点缓存、生成新的控制凭据、验证内核配置，再切换服务。原配置和缓存保留。新内核通过带凭据的本机检查后才关闭旧服务的开机启动；切换失败则保留失败目录、恢复旧代理并重新启动应用。

默认应用目录和数据目录为 `/opt/sub2api`；自定义数据目录需将实际的 `DATA_DIR` 传给升级脚本。已有受管目录不会覆盖。迁移只识别旧安装器创建的单个 airport provider；自定义旧内核配置需人工迁移。迁移暂存目录与目标目录跨文件系统时会安全失败，旧代理尚未停止。

## 当前限制及发布前工作

- 仅网页二进制自更新没有 root 权限，不能执行旧 systemd 服务迁移；需要经 root 升级入口完成一次迁移。网页不会尝试提权或覆盖现存内核。
- 已在原生 Linux amd64、非 root 只读根目录容器及 ARM64 用户态模拟环境验证内核安装、模拟订阅、主进程管理、用后移出和迁移。ARM64 是 QEMU/PRoot 运行验证，不是原生 ARM64 硬件实测；未使用真实机场或模型额度。
- 网页组件以模拟 API 做浏览器交互测试，不等同已验证完整生产认证链路。
- ticket 侧已实现结构化完成事件校验、候选时间校验、公平轮询、主备缓存和 HTTP 响应头形态异常后的撤销/提升。严格模式默认关闭；开启后在已注入票据且 HTTP 响应头明确不匹配时关闭上游正文，返回不可自动故障转移的错误。当前请求可能已被上游计费且无法取得完整 usage；不会自动重放。不声称覆盖原生 WebSocket 中的 state 事件。
- systemd 用户级真实服务的迁移和旧服务恢复已在隔离目录验证；未重启生产服务或执行生产 root 迁移。上线时仍需按正常部署流程验证真实实例。

## 验证方式

常规测试使用本地模拟服务：`go test -race ./internal/mihomo`。

可选官方内核安装冒烟测试：`MIHOMO_INSTALL_SMOKE=1 go test ./internal/mihomo -run TestOfficialKernelInstallation -v -count=1`。该测试下载官方内核，订阅和出口均使用本地模拟服务，不调用模型、不使用生产订阅或更改生产服务。

增加 `MIHOMO_SYSTEMD_SMOKE=1` 可在有 systemd 用户会话的 Linux 上测试独立的临时服务迁移与恢复。容器 ARM64 模拟环境的构建文件为 `deploy/tests/mihomo-arm64.Dockerfile`；挂载 ARM64 交叉编译的 mihomo 包测试二进制到 `/tests`，仅在测试容器内放宽 seccomp 供 PRoot 使用，不安装宿主机 binfmt 处理器。
