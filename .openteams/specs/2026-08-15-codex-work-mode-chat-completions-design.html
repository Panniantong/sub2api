GPT-5.6 Work Mode 全入口支持

目标：让符合条件的 OAuth 请求明确以 Work Mode 身份发往上游，并能从模型名、出站身份与成功 usage 三层证据验收。

一、正确链路

客户端 gpt-5.6-sol → New API 映射为 gpt-5.6-sol-wm → Sub2 在选号前归一为 gpt-5.6-sol → OAuth 出站写入 originator: codex_work_desktop 与 Codex Desktop User-Agent → 客户端仍看到原请求模型。

二、实现范围

  • 覆盖 /v1/responses HTTP、Responses WebSocket，以及两个 Chat Completions handler。
  • gpt-5.6、Sol、Terra、Luna 默认启用；显式 *-wm 始终启用。
  • 在 composite/channel/account 选择前统一使用基础模型，避免 model_not_found。
  • OAuth 的 Responses 出站注入 Work 身份；API Key、非 GPT-5.6 和生图请求不注入。
  • usage 的 requested/client model 保留客户端名称；upstream/billing/scheduling 使用基础模型。
  • gateway.disable_codex_work_mode=true 只关闭普通模型的默认启用，不关闭显式 *-wm。

三、失败与回滚

  • 任何入口仍把 *-wm 送入账号能力匹配，即视为失败，不部署。
  • 真实请求只有 200、但无法证明 Work 身份，不算验收通过。
  • 渠道映射最后开启；若 Chat/Responses 任一出现新增 404，立即恢复已保存的渠道 6–10 映射快照。
  • 四实例逐个滚动替换，保持其余实例承接流量；不操作 edge-gw。

四、测试与生产验收

  1. 单测：默认开启、配置关闭、显式后缀、Chat 流式/非流式、Responses HTTP/WS、API Key 不受影响、响应模型与 usage 语义。
  2. 回归：internal/service、internal/handler、internal/config 全包通过。
  3. 部署后开启渠道 6–10 的 Sol/Terra/Luna 显式 → *-wm 映射。
  4. 真实验收至少包含一笔 Chat 和一笔 Responses 成功请求；数据库必须显示 requested_model=*-wm、upstream_model=基础模型。
  5. 出站 capture 或等价脱敏证据必须确认 originator=codex_work_desktop 和 Codex Desktop UA。
  6. 观察 404、503、502、成功率、FRT 和实例重启次数；全部无回归后才宣告完成。

五、完成定义

不是“模型能返回”，而是 Chat 与 Responses 都成功、显式 WM 可审计、出站身份可证明、普通请求无新增回归，并保留可立即恢复的生产映射快照。
