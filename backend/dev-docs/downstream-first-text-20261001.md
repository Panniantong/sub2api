# 接入方实际首字优化（2026-10-01）

本轮优化普通 HTTP 流式请求的实际发送路径，保持 `first_token_ms` 统计配置不变。

## 修改

- Responses 首个有效事件在完整 SSE 边界立即刷新，不再依赖读取队列清空。
- 首段正文有独立的刷新状态。之前推理/工具内容已触发首个可见输出刷新时，第一段正文仍可能合并进后续突发事件；现在正文独立触发一次刷新。后续事件继续批量发送。
- 构造上游请求时，绑定 Host 的 Cookie 从不可变内存索引读取，避免反复查询并解析整个 Cookie 库。快照缓存一秒，未命中/过期时合并并发读取；本进程库写入成功后立即发布新快照。每次读取仍独立校验 Cookie 过期时间。
- 管理页面、获取来源的新旧判断和调度准入的权威读取仍走原有数据库路径。写库和快照加载串行化，避免较慢的旧读取覆盖刚写入的新 Cookie。保存失败不更新快照，过期快照读取失败也不回退到旧 Cookie。

其他进程直接修改同一数据库时，请求构造中的 Cookie 快照最长约一秒后重新读取；当前实例的正常采集、响应异步更新、删除都立即发布。未变更 Cookie 格式、下游 Cookie 回显、获取日志、计费、模型或推理强度。

## 验证

- 新增“推理先到、正文和后续事件排队”的回归：旧实现仅刷新两次，未及时单独刷新首段正文；修改后通过。
- 两层真实 HTTP 流式转发测试：上游在接入方读到正文前不允许发送完成事件，验证正文提前到达、增量内容原样保留、两跳 usage 完整。
- Cookie 快照测试覆盖并发冷读、Host 隔离、更新/删除立即生效、调用方修改隔离、过期 Cookie 拒绝、外部更新重读和存储失败。响应 Cookie 新旧判断测试同时检查请求快照。
- 首字/CPA、首输出超时、可见内容以及流式刷新相关回归通过；Cookie Dispatch/Refresh/Acquisition/Host/Degraded、响应 Cookie 同步定向回归通过。
- 本轮未宣称全仓库测试通过。扩展 Cookie 筛选命中了此前已知的旧用例失败；针对本次改动的上述回归通过。
- 100 Host 本地基准（不含真实数据库往返）：整库读取解析 `133631 ns/op`、`61538 B/op`；快照命中 `47.43 ns/op`、零分配。它只代表 Cookie 查找环节，不能作为端到端提升比例。
